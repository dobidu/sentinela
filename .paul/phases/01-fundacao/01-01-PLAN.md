<objective>
## Goal
Deixar o repositório com um app Next.js (App Router, TypeScript strict, pnpm) que passa em `lint`, `typecheck`, `test` e `build` localmente e num pipeline do GitHub Actions disparado em push/PR para `main`.

## Purpose
Base de todas as fases seguintes. A decisão "CI/CD desde o início" (PROJECT.md) exige que cada plano posterior já nasça com o gate automático; a entrega acadêmica exige repositório reprodutível (`pnpm install && pnpm build` funciona numa máquina limpa).

## Output
- App Next.js mínimo em `src/app/` (página placeholder "Sentinela")
- Harness de teste Vitest + Testing Library com 1 teste de fumaça
- Scripts padronizados em `package.json`: `dev`, `build`, `start`, `lint`, `typecheck`, `test`, `test:coverage`
- `.github/workflows/ci.yml`
- Seção "Desenvolvimento" no README.md
</objective>

<acceptance_criteria>

## AC-1: App Next.js sobe e compila
```gherkin
Given um clone limpo do repositório com Node 24 e pnpm
When rodo `pnpm install --frozen-lockfile && pnpm build`
Then o build termina com exit 0
And `pnpm dev` serve em http://localhost:3000 uma página com o texto "Sentinela"
```

## AC-2: Gates de qualidade locais
```gherkin
Given o app scaffoldado
When rodo `pnpm lint`, `pnpm typecheck` e `pnpm test`
Then os três terminam com exit 0
And `pnpm test` executa ao menos 1 teste (fumaça da página inicial) que passa
And `pnpm typecheck` roda `tsc --noEmit` com `strict: true`
```

## AC-3: Gate falha quando deve
```gherkin
Given o harness de teste configurado
When introduzo temporariamente uma asserção falsa ou um erro de tipo
Then `pnpm test` / `pnpm typecheck` terminam com exit ≠ 0
And a alteração temporária é revertida antes de concluir a task
```

## AC-4: Pipeline de CI válido e verde
```gherkin
Given `.github/workflows/ci.yml` no repositório
When o workflow é validado com actionlint
Then não há erros
And, após push para `main` (checkpoint humano), o run "CI" no GitHub termina com sucesso executando install → lint → typecheck → test → build
```

## AC-5: Arquivos existentes preservados
```gherkin
Given README.md, LICENSE e .gitignore já versionados
When o scaffold é aplicado
Then LICENSE fica intacto
And README.md mantém o conteúdo atual, com a seção "Desenvolvimento" acrescentada
And .gitignore mantém todas as entradas atuais (incluindo `.claude/`), apenas acrescidas das que o Next.js precisa e ainda não existem
```

<!-- audit-added -->
## AC-6: Reprodutível a partir de árvore limpa
```gherkin
Given uma cópia do repositório sem `node_modules/`, `.next/`, `coverage/` nem `next-env.d.ts`
When rodo a sequência do CI (`pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test:coverage && pnpm build`)
Then todos os passos terminam com exit 0 na ordem do CI (typecheck ANTES do build)
And o install não emite aviso/erro de build scripts ignorados ("Ignored build scripts") nem falha por scripts não aprovados
And `pnpm lint` continua exit 0 mesmo depois de `coverage/` e `.next/` existirem
```

<!-- audit-added -->
## AC-7: Supply chain do CI controlada
```gherkin
Given o workflow de CI num repositório público
When inspeciono `.github/workflows/ci.yml`
Then toda action de terceiro está fixada por SHA de commit completo (com a tag em comentário)
And o checkout usa `persist-credentials: false` e o job tem só `contents: read`
And `.github/dependabot.yml` mantém atualizações semanais para `github-actions` e `npm`
```
