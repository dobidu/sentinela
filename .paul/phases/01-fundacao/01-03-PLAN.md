<objective>
## Goal
Colocar o Sentinela no ar em nuvem gerenciada: banco Supabase em São Paulo com o schema de 01-02 aplicado por um job de CD após CI verde, app Next.js servido pela Vercel com deploy automático a partir de `main` (preview em PR), e `main` protegida por checks obrigatórios.

## Purpose
Entregável "MVP no ar" e reprodutibilidade para o artigo: qualquer commit em `main` passa por CI, aplica migrations de forma controlada e publica o app — sem passo manual esquecido. Região sa-east-1 mantém dado pessoal de cidadão brasileiro no Brasil (LGPD).

## Output
- Projeto Supabase `sentinela` (sa-east-1) com migrations 01-02 aplicadas, sem seed
- Projeto Vercel `sentinela` ligado ao repo GitHub, região de funções `gru1`, env vars públicas do Supabase configuradas
- Job `deploy-db` no CI (environment `production`), secrets no GitHub
- Branch protection em `main` exigindo `quality` e `database`
- README: seção "Deploy" + correção das seções desatualizadas "Status" e "Roadmap"
- `.env.example` documentando variáveis
</objective>

<acceptance_criteria>

## AC-1: Banco remoto com schema e sem seed
```gherkin
Given o projeto Supabase `sentinela` criado em sa-east-1
When as migrations de `supabase/migrations/` são aplicadas
Then `supabase migration list --linked` mostra as 2 migrations como aplicadas local e remotamente
And `public.municipality` está vazia no remoto (seed não aplicado)
And `supabase db advisors --linked --type security` não reporta warnings
And o role `anon` não lê nenhuma tabela de `public` via API REST do projeto (HTTP 401/403 ou lista vazia por falta de privilégio — nunca linhas)
```

## AC-2: App em produção
```gherkin
Given o projeto Vercel ligado ao repo `dobidu/sentinela`
When um commit chega em `main`
Then a Vercel publica automaticamente em produção
And a URL de produção responde 200 com `<h1>` "Sentinela" e `lang="pt-BR"`
And um PR gera deploy de preview
And `NEXT_PUBLIC_SUPABASE_URL` e `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` existem nos ambientes production e preview
And nenhuma chave secreta (service_role / secret key / senha do banco) está configurada na Vercel
```

## AC-3: CD de migrations controlado
```gherkin
Given o job `deploy-db` no CI
When há push em `main` e `quality` + `database` passaram
Then o job faz `supabase db push` no projeto remoto sem `--include-seed`
And roda no environment `production`, com concorrência serializada (nunca dois pushes simultâneos, nunca cancelado)
And em pull requests e forks o job não roda e não tem acesso aos secrets
And quando não há migration nova, o job termina verde sem alterar o banco
<!-- audit-added -->
And o job usa apenas uma credencial escopada ao projeto (`SUPABASE_DB_URL` via session pooler) — nenhum access token de conta Supabase existe no GitHub
And o job não executa `pnpm install` nem código de dependências npm enquanto tem secrets no ambiente (CLI via `supabase/setup-cli` fixado por SHA, mesma versão do package.json)
And nenhum dump/dado do banco vai para log ou artifact
```

<!-- audit-added -->
## AC-6: Produção só com CI verde e Auth fechado
```gherkin
Given um commit em `main` cujo CI falha (lint/test/database)
When a Vercel builda o commit
Then o deploy NÃO é promovido a produção (Deployment Checks exigem os checks do GitHub)
Given o projeto Supabase remoto
When alguém tenta `POST /auth/v1/signup` com a publishable key
Then o cadastro é recusado (signup público desabilitado — só staff criado por admin)
Given o repositório público
Then secret scanning e push protection do GitHub estão habilitados
```

## AC-4: main protegida
```gherkin
Given a branch protection de `main`
When abro um PR com `quality` ou `database` falhando
Then o merge fica bloqueado
And force-push e deleção de `main` são recusados
```

## AC-5: Segredos e documentação
```gherkin
Given o repositório público
When inspeciono arquivos versionados, logs do CI e env vars da Vercel
Then nenhuma senha, access token ou service_role key aparece
And `.env.example` lista as variáveis necessárias sem valores reais
And o README documenta o fluxo de deploy e tem "Status" e "Roadmap" atualizados
```
